# Contribution Readiness

## Fit

- Confirm the receiving project owns the behaviour.
- Link prior discussion or request maintainer agreement for substantial work.
- State scope and non-goals.
- Avoid duplicating an accepted solution.

## Evidence

- Provide minimal reproduction and supported versions.
- Distinguish observation, inference, and expected behaviour.
- Identify affected people and tasks.
- Link specifications, documentation, tests, and prior decisions.
- Remove private data and unrelated logs.
- Include an automated regression test when feasible and project-supported.
- If automation is omitted, explain why and provide appropriate manual,
  visual, or documentary evidence.

## Change

- Keep one coherent purpose.
- Follow project architecture and style.
- Include appropriate tests and documentation.
- Avoid unrelated formatting, refactoring, dependencies, and generated files.
- Verify the final diff and description agree.

## Gates

- Accessibility and manual testing where relevant.
- Security boundaries and private disclosure.
- Privacy and data minimization.
- Copyright, license, attribution, CLA, and DCO.
- Compatibility and release impact.
- Sustainability and maintainer burden.

## Human responsibility

- Understand every material change.
- Record tests actually run.
- Disclose material AI use when required.
- Remain available to answer and revise.
- State promptly if unable to continue.
