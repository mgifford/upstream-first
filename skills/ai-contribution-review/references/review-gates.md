# AI Contribution Review Gates

## Fit and scope

- Confirm project ownership and prior agreement where required.
- Keep one coherent purpose.
- Remove unrelated formatting, refactoring, dependencies, and generated text.
- Ensure issue or pull-request descriptions match the final state.

## Human accountability

- Understand material lines, claims, and design choices.
- Be able to revise without blind regeneration.
- Remain available for review.
- State uncertainty rather than generating confidence.

## Verification

- Verify package names, APIs, standards, citations, and links.
- Run deterministic tests and checks.
- Record only tests actually run.
- Review tests for meaningful behaviour rather than generated volume.
- Compare against analogous accepted project work.

## Accessibility

- Identify affected disabled people and tasks.
- Check semantic structure, keyboard behaviour, focus, contrast, reflow, names,
  instructions, and manual evidence where relevant.
- Do not treat automated results as complete conformance.

## Security and privacy

- Prevent secrets, personal data, private code, or embargoed vulnerabilities
  from entering unauthorized tools or public records.
- Preserve authentication and authorization boundaries.
- Validate untrusted input and generated commands.
- Verify new dependencies and supply-chain claims.

## License and provenance

- Confirm contribution rights.
- Meet license, attribution, CLA, DCO, and sign-off rules.
- Check copied or closely generated material.
- Disclose material assistance as required.

## Sustainability and maintainability

- Prefer deterministic methods over repeated model calls.
- Reduce generated size and complexity.
- Avoid needless dependencies and new packages.
- Account for human review cost and long-term ownership.
